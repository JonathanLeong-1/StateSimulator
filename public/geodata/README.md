# Bundled geodata (`public/geodata/`)

Compact, preprocessed geographic datasets consumed by the real-world map
rasterizer (architecture §5). These assets are generated by
[`scripts/geodata/build-geodata.mjs`](../../scripts/geodata/build-geodata.mjs)
and are fetched once by the in-browser core and the Node build script.

The real-world map pipeline samples these global rasters, projects them through
an **equal-area (Equal Earth)** projection, and rasterizes the result into
**per-hex terrain** for a user- or generator-selected region (architecture §3,
§6). The bundle is deliberately the *raw, accurate* source: classification and
projection happen downstream in WS2 — these files prioritise **geographic
accuracy over aesthetics** and carry no smoothing (see _Geographic-accuracy
policy_ below).

> **Provenance:** whether the *currently committed* assets are real-world data
> or synthetic placeholders is recorded per-layer in
> [`PROVENANCE.json`](./PROVENANCE.json). If a `SYNTHETIC.txt` file is present,
> at least one layer is a placeholder and should be regenerated with real data
> (see _Regenerating_ below).

## Files

| File | Format | Description |
|------|--------|-------------|
| `manifest.json` | JSON | Asset manifest — architecture §5 schema (consumed by WS2). |
| `elevation.bin` | raw `Int16`, little-endian, row-major | Elevation in metres on a 2160×1080 global grid. |
| `koppen.bin` | raw `Uint8`, row-major | Köppen–Geiger class codes (0–30) on the same grid. |
| `rivers.geojson` | GeoJSON (WGS84) | 477 river centreline `LineString`/`MultiLineString` features, `name` attribute only, 5-decimal coordinate precision. |
| `koppen_legend.txt` | text | Köppen code → symbol legend (copied from source, real builds only). |
| `PROVENANCE.json` | JSON | Per-layer source/license + real-vs-synthetic record. |
| `SYNTHETIC.txt` | text | Present **only** when ≥1 layer is a synthetic placeholder; absent for a fully real bundle. |

### Raster layout
- **Grid:** `width × height = 2160 × 1080` (≈ 1/6° per cell).
- **Bounds:** `[-180, -90, 180, 90]` (whole globe, incl. Antarctica).
- **Orientation:** row-major; **row 0 = north edge (lat +90)** descending to
  the south; **col 0 = west edge (lon −180)** increasing east.
- **Indexing:** `index = row * width + col`.
- **Elevation:** `Int16` metres, little-endian. `seaLevel = 0`; a cell is ocean
  when `elevation ≤ seaLevel`.
- **Köppen:** `Uint8` class code; `0` = ocean / no-data, `1–30` = Köppen classes.

### Köppen class codes (canonical 1–30)
`1 Af · 2 Am · 3 Aw · 4 BWh · 5 BWk · 6 BSh · 7 BSk · 8 Csa · 9 Csb · 10 Csc ·
11 Cwa · 12 Cwb · 13 Cwc · 14 Cfa · 15 Cfb · 16 Cfc · 17 Dsa · 18 Dsb · 19 Dsc ·
20 Dsd · 21 Dwa · 22 Dwb · 23 Dwc · 24 Dwd · 25 Dfa · 26 Dfb · 27 Dfc · 28 Dfd ·
29 ET · 30 EF` (`0` = ocean/no-data). WS2 maps these to biomes per architecture §6.1.

## Geographic-accuracy policy
The bundle prioritises **geographic accuracy over aesthetics**. No smoothing is
applied:

- **Rasters** are downsampled with **nearest-neighbour** resampling
  (`gdalwarp -r near`, no value blending), preserving real local variance for
  downstream ruggedness analysis.
- **River geometry** is taken directly from Natural Earth's 50m product with
  **no additional simplification** (`ogr2ogr`, no `-simplify`). The 50m product
  is itself the already-generalised source; we add zero cleanup.
- Island removal, lake removal, and biome smoothing are explicitly avoided — the
  output reflects the source data exactly at this grid resolution.

The **one** transformation that drops data is a validity filter, not smoothing:
river features whose geometry is `NULL` are excluded
(`ogr2ogr -where 'OGR_GEOMETRY IS NOT NULL'`). A null-geometry feature carries
no coordinates and would break the WS2 river hit-test; removing it changes no
real river line.

## Regenerating

### Prerequisites
- **Node.js** ≥ 18 (the build script is a native ESM `.mjs`; no npm install needed).
- **GDAL** on `PATH` — specifically `gdalwarp` (raster warp/convert) and
  `ogr2ogr` (vector convert). `gdal_translate` is **not** used.
- **`curl`** and **`unzip`** for fetching/extracting sources.
- Network access (to download the source datasets).

Install GDAL via your platform package manager, e.g. `brew install gdal`
(macOS) or `apt-get install gdal-bin` (Debian/Ubuntu).

### Commands
```sh
# Build ALL layers from real sources.
# Downloads ~560 MB of sources to scripts/geodata/.cache/ (git-ignored).
node scripts/geodata/build-geodata.mjs

# Rebuild only a subset (comma-separated). Layers NOT listed keep their
# existing bytes AND their PROVENANCE.json entry (provenance is merged, not
# clobbered), so a partial rebuild is safe.
node scripts/geodata/build-geodata.mjs --only=koppen,rivers

# Force synthetic placeholders for every layer (offline / CI smoke test).
# Writes a SYNTHETIC.txt marker and flags each layer real:false in PROVENANCE.
node scripts/geodata/build-geodata.mjs --synthetic

# Validate the emitted bundle (dims, byte sizes, river feature integrity).
node scripts/geodata/verify-geodata.mjs
```

Each layer builds independently: if a real source can't be fetched (no network,
source moved, GDAL missing), **only that layer** falls back to a clearly
labelled synthetic placeholder so downstream workstreams stay unblocked. The
real-vs-synthetic status of every emitted asset is recorded per-layer in
[`PROVENANCE.json`](./PROVENANCE.json).

### Caches
Downloaded sources and intermediate conversion artifacts are cached under
[`scripts/geodata/.cache/`](../../scripts/geodata/.cache) — **git-ignored**
(see [`scripts/geodata/.gitignore`](../../scripts/geodata/.gitignore)) because
they are large (~560 MB) and fully reproducible. Only the compact outputs in
`public/geodata/` are versioned. Re-runs reuse the cache and are incremental.

### Manifest schema
`manifest.json` follows the **frozen architecture §5 schema** exactly (no extra
keys) and is the contract WS2 consumes. The grid contract
(`2160 × 1080`, bounds `[-180,-90,180,90]`, `seaLevel: 0`) is fixed by §5 and
must not drift.
